# Fable review and dispositions

Fable5 reviewed protocol correctness and cold-start agent UX in read-only mode at high effort. Its full original draft review is retained as a user-facing artifact. This document records fixes, not a claim of production security certification.

Release blockers addressed:
- Strict validation now applies to both leader and independent validator outputs. Settlement additionally bounds and deduplicates eligible recipients. Tests cover forged ids/references and independent disagreement.
- Only the enrolled executor can request adjudication/review and finalize/settle. It requires successful, non-leader-only finalized receipts with independent agreement for merit decisions. Exact challenge-round arguments are bound in receipts using typed ABI encoding. Contributor keys cannot mint through leader-only calls.
- Stale unmerged records can expire with executor-attested reasons, releasing their statement reservation. Credited work cannot expire. The worker rereads actual canonical refs and PR head before finalization/merge and handles interrupted recovery.

Further fixes: migration must precede live registration; already-reserved statements are rejected before allocating a slot; legacy GitHub-author provenance is explicitly passed to impact review; actual bounded proof text is included; proof use is normalized for discarded arguments/bindings/projections; all policy pins are checked; signatures have a one-minute posting-clock margin; jobs are serialized after eligibility checks and an inexpensive bounded sweeper recovers displaced work; saved reports cannot replace signed evidence; operator secrets are scoped to the protocol environment.

Agent UX now includes a static guide, machine-readable entry, live open-goal query, required record generator/formatter/checker, local or external wallet signing, public status, challenge preview/submission and recovery instructions. The narrow enrollment limit is explicit. Both statements will be closed after the downstream pilot; additional rewarded research needs a reviewed policy expansion. Fork submissions are supported by the design but have not yet been independently tested with another GitHub account.

Validation at this checkpoint:54 Node tests,51 Python contract/proof tests (including actual Lean4.19.0 execution), GenVM validation, clean dependency audit, and desktop/mobile guide walkthrough. Native v2 end-to-end results are recorded separately once observed.

The targeted Fable follow-up reached its configured10-step limit before producing a final verdict. It was investigating integer receipt decoding; that issue was independently fixed and regression-tested. The follow-up is not represented as approval. A subsequent SDK audit also corrected finalized reads to use transactionHashVariant=latest-final; the earlier stateStatus option was ignored. Historical400points were reread successfully from the explicit finalized snapshot.

Remaining limits include trusted operator/administrator roles, both GitHub checks using Actions app15368, only100 pilot records, free-wallet abuse of the two challenge slots, no proof of distinct humans, bounded reviewer context/global-novelty uncertainty, and best-effort scheduling. These need production redesign and additional independent adversarial review.

## V3 follow-up review and fixes

Fable 5 completed a separate read-only, high-effort review of v3 correctness and agent UX. It found no P0 in its reading and reported three P1 recovery/liveness issues plus attribution and onboarding gaps. This is an independent review, not approval or a security certification. It ran 32 focused Node tests; the parent separately ran the full native-contract and Lean suites.

The resulting fixes scope external allocations to authors whose own source has corroborated priority; reserve source nodes before a proof can be merged; expose source-specific author IDs and URLs; fail closed on unsupported protocol versions; and provide target/source/capacity checks plus withdrawal of unadmitted reports. The direct-author identity flow requires the exact challenge on the same registered source, with a documented 24-hour end-to-end deadline. Immutable academic identity adapters remain unimplemented.

Recovery now persists an exact typed-call intent before broadcast, recovers missing hashes from native history and re-reads saved receipts from Studio. Failed or uncertain reviews are not rerolled. Only enrolled-sender history counts toward the decoding bound, so other wallets cannot trip the 1,000-row limit. A registration interrupted after broadcast remains resumable. Terminal workers reconcile review and settlement receipts before marking a job complete. Scheduled cases skip repeated errors at the same round/configuration while explicit recovery remains available. Every first attestation re-fetches source bytes and native identity pins. Native local journals use atomic replacement and filesystem sync.

Source admission checks mirror identity pins, capacity, Unicode lengths, actual retrieval timestamps and total attestation size before signing. The source collector still cannot establish global priority or identity by itself. Known limits include 500 affiliation wallets, bounded author/record registries and case scans, Studio's history API, operator-managed documentary admission, immutable pilot identity bindings, and missing prepared bytes requiring operator recovery. Corrected-recipient later-impact routing remains deliberately unavailable.

The overnight Sol review reproduced a terminal-state race in deployed v3 `expire_case`: an executor transaction started before reporter withdrawal can debit the same active-case slot twice after the case becomes objectively stale. An authorship claim's 24-hour expiry is sufficient staleness. With one unrelated active case, the reproduced state changed from `(withdrawn, 1 active)` to `(expired, 0 active)` while points and the unrelated case remained unchanged. The reporter cannot call expiry. The immediate mitigation removes worker initiation of documentary expiration; stale cases fail closed and repeated failures do not block later queue work. Native contract bytes remain frozen. A future replacement must return without mutation for both `expired` and `withdrawn`, with direct regressions for zero/one remaining active cases and a complete migration plan. This mitigation trades automatic stale-slot cleanup for preserving quota/history correctness.
