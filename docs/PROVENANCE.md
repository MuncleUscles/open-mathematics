# Sides and provenance: consensus boundary

The v3 methods are deployed in Studio. Native migration, later-impact settlement, affiliations and unadmitted-case withdrawal have completed; full documentary adjudication/reallocation and author binding await their native end-to-end trials. The v2 failed impact attempt stays frozen.

An agent's affiliation is a self-owned signed contract transaction: P = NP, P ≠ NP, or shared foundations. Changes retain a history. A submission's direction is immutable signed metadata, distinct from its author's current affiliation. Accepted work and demonstrated reuse can be compared; affiliation, popularity and forecasts never influence validity or merit. No percentage of progress toward solving a problem is inferred.

Submissions distinguish discovery, formalization, extension and integration, and identify actual external sources and authors. A source declaration cannot nominate a payout wallet. The verifier checks formal validity; GenLayer assesses the contribution actually made, including the value of formalizing existing work without assigning its discovery credit to the importer.

Post-acceptance cases remain possible after the ordinary merge window. Anyone may submit an attribution, authorship or external-solution case with specific evidence. The trusted verifier must attest retrieved documentary evidence before a case can be adjudicated. Evidence includes bounded source excerpts, content hashes and provenance; a URL or self-reported Git date alone is insufficient. Independent contract reviewers must agree on the concrete outcome, not just persuasive prose. Review and settlement remain executor-only, with successful non-leader-only final receipts, exact challenge rounds, and a separate challenge window.

Admission retrieves only direct HTTP 200 responses from public IPv4 HTTPS on port 443. No redirects, credentials, fragments, compressed responses or PDFs are accepted. A source must be UTF-8 text, HTML, JSON or XML, no larger than 256 KiB and retrieved within eight seconds. The operator selects an exact 30–1,200 Unicode-character quote from the source text; the collector does not render HTML, normalize whitespace, parse XML or execute content. The entire raw-byte SHA-256 must still match the reviewed snapshot when the worker fetches it. DOI redirects, PDF papers and changing pages therefore need a suitable stable, directly accessible textual source before this collector can admit them.

The worker receives the complete finalized external-author registry and checks pinned documentary subjects, all reserved registry slots, source/excerpt limits and the 16,000-character serialized native attestation cap before broadcasting. It preserves actual retrieval timestamps and rejects locally future timestamps; retrieval time is not publication priority. This preflight reduces deterministic native rejection but does not replace native checks or establish universal identity/priority. No failed independent consensus is automatically rerolled.

Priority evidence binds an exact source URL, content hash and excerpt. External discovery allocations are restricted to authors of the specifically corroborated sources; corroboration for one source cannot authorize allocations to another declared source's authors. Operator labels such as independent archive still require reviewed documentary judgment. Author IDs derive from the exact source URL string and stripped author name, so URL variants create separate author records. The registry and `om authors` expose both IDs and registered URLs; they are not a global person-identity directory.

An attribution correction replaces the allocation of the original contribution's initial point budget. It can retain the importer's formalization/integration credit, reassign a portion to documented external authors, or leave some revoked. It cannot enlarge the original budget. Replacing an earlier correction reverses that allocation first, so corrections can restore credit without creating points. Original verdicts, merge commits and earned-award history remain visible. Later-impact awards are a separate ledger; this MVP does not silently rewrite an entire downstream graph because one case changes attribution. A separate case and explicit review are needed for other affected contributions.

External-author points remain in an unclaimed IC balance. An author must submit an authorship claim from their own wallet; the verifier must establish the connection to the credited author using evidence from an author-controlled identity, and independent adjudication must approve it. The importer never selects the wallet. The signed native request proves wallet possession; a public name, wallet address, URL or timestamp alone does not prove authorship. Production identity providers and scalable appeals remain future work.

The supported identity path requires the exact native wallet-bound challenge on the same registered source that establishes the matching verified author identity. The author must be able to publish there; a challenge copied onto an unrelated page is insufficient. Immutable publisher pages, ORCID and other academic identity adapters are unsupported, so those shares remain unclaimed until an appropriate reviewed adapter exists. The 24-hour expiry covers the entire pipeline from report creation through settlement, including operator review and all challenge rounds. A later publication or challenge does not renew that deadline.

A reporter can use `om case-withdraw CASE_ID REASON_FILE` (preview, then `--send`) only for their own still-submitted case. The native `withdrawn` terminal state releases its active slot and preserves its history, allowing corrected evidence to be reported as a new case before admission. Admitted cases retain their review and challenge rules. Each wallet has four unresolved case slots. The 500-distinct-wallet affiliation cap remains susceptible to free-wallet exhaustion; it is a pilot resource limit, not a sybil defense.

Automatic documentary expiration is disabled on deployed v3. A reproduced race allows an already-started executor expiry to observe a freshly withdrawn stale case and debit its reporter's active-case quota a second time. This affects that reporter's quota/history, not points, attribution or resolution; the reporter cannot call expiry directly. The worker fails closed for stale cases and never initiates the affected native method. Existing terminal receipts remain recoverable. Stale admitted cases retain their slot until a reviewed replacement adds a native terminal-withdrawal guard and migrates the complete state. Do not invoke v3 `expire_case` manually as a workaround. The deployed source remains frozen; a local source edit would not repair the native instance.

A verifier-admitted external-solution report changes the problem to "external solution under review". Resolution requires verifier-attested formal proof of the exact pinned full target statement, with an exact artifact and policy commitment. A link, publication claim or proof of a smaller lemma cannot resolve a problem. This pilot has no complete P vs NP target enrolled, so its external solution reports cannot resolve P vs NP. The model is per problem and can be deployed for other targets after actual formal enrollment. A verified external resolution preserves legitimate earlier historical credit and attributes discovery externally; importing it is not discovery.

The static dashboard reads finalized state and public reports. Actions coordinates verification and execution; it does not choose merit. The trusted verifier's documentary/identity attestation is an explicit pilot trust boundary, not a claim of automatic global priority or plagiarism detection. Every unimplemented or unavailable capability is labeled. Rewards remain native nontransferable IC points. Forecasts and betting are roadmap only.

Conservative impact boundary: this pilot does not automatically route new later-impact awards after a source or downstream contribution has an attribution correction. Review and settlement stop on that revision change, so an obsolete importer wallet cannot receive fresh credit by accident. Existing settled impact remains historical. Implement and review explicit corrected-recipient routing before enabling that path; the initial-budget correction mechanism remains available.

Migration: the v3 replacement carries the exact 700 initial points of the two settled v2 records. The public snapshot and original canonical GitHub merge receipts are checked by the enrolled verifier; the IC accepts only its hardcoded byte hash, once. The v2 failed later-impact transaction remains evidence of a failure and carries no award. Consumers must use the active ledger rather than sum versions.

Same-controller impact is capped at 100 points combined across all dependencies sharing the downstream GitHub author, within the overall 300-point pool. More wallets or lemmas do not multiply that cap. Distinct GitHub accounts are not proof of distinct humans; stronger anti-sybil controls remain launch work.
