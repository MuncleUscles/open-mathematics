# Disclosed open-research pilot examples

These are newly packaged, known SAT facts for a same-project integration trial, not mathematical discoveries or independent outside research. No task ID or curator-selected statement is needed.

- `locality.json` defines a small CNF representation and proves that assignments agreeing on all occurring variables give the same evaluation. The transport argument is adapted from the openly published [disjoint-CNF reference](https://github.com/MuncleUscles/open-mathematics/blob/27373fa9d84bf8e489ce03b7b930bf69e2251a29/proposals/disjoint-cnf/candidate.proof), extended here to Boolean equality. This prior source must be disclosed in any contribution record. Core List lemmas supply membership/evaluation facts.
- `finite-support.json` imports locality and proves that satisfiability has a witness that assigns false outside the formula's finite variable support. Its proof invokes the imported theorem to preserve the witness's evaluation. This is useful model normalization, not a new SAT algorithm, complexity bound or P-versus-NP result.

The downstream dependency ID `pilot-locality` is an example identifier, not a live native record. Before a real submission, replace it with the actual accepted upstream record ID, retain the upstream's exact committed bundle hash, and have the trusted worker resolve its immutable accepted bytes and raw artifact commitment. The `B_<raw bundle SHA256>` namespace is deterministic; each bundle exports its named definitions and theorem `result`. Different pilot wallets controlled by the same GitHub account must be disclosed as common control. The contract, not these examples, decides merit, merge and any retrospective points.

## Bundle and verifier boundary

A normalized JSON bundle has exactly `version:1`, `definitions`, `statement`, `proof`, and `dependencies`. Each definition has exactly `name`, `type`, `value`; definitions are sequential, nonrecursive pure expressions. Each dependency is exactly `{id,bundle_hash}`. There are at most eight definitions, four direct dependencies, eight total imported artifacts and four dependency edges of depth. Total bundle bytes are at most 32 KiB, imported closure 256 KiB, statement 4,000 bytes and proof 12,000 bytes.

This deliberately limited language supports Core Nat, Bool, List, Option, products and elementary constructive logic, plus explicitly listed constructive tactics including `simp`, `rw`, `induction` and `omega`. It does not support arbitrary Lean programs, imports, custom inductives, macro/elaborator code, IO, strings, comments, recursive declarations or Mathlib. The contributor still chooses definitions and proposition; the limits are an execution-language boundary, not a mathematical task catalog. Proofs begin with `by` and a newline. See `lean/open_check.py` for the exact lexical vocabulary.

Run the trusted `scripts/verify_open.py BUNDLE --policy FILE --policy-hash SHA --dependencies MANIFEST --head SHA40 --base SHA40 --protocol-commit SHA40 --repository owner/repo`. `--bundle FILE` is an alternative to the positional bundle. The worker-created manifest is `{version:1,artifacts:[{id,bundle_hash,artifact_hash,path}]}` with exact accepted local JSON files, never source URLs. Stable `artifact_hash` and `bundle_hash` both identify the exact accepted JSON bytes. The verifier recompiles and audits the complete dependency closure under the current checker; `assembly_hash` separately attests the exact generated two-file check, including its fresh audit nonce. A checker change therefore does not rewrite prior artifact identities.

Contributor expressions compile in an Init-only candidate module. A separate trusted Lean inspector checks every declaration against the kernel environment, rejects root-name collisions and forbidden axioms, and emits one nonce-bound compact machine report; unexpected stderr fails the check. Production uses the pinned `TRUSTED_LEAN_IMAGE` with no network, read-only filesystem, nonroot user and bounded resources. `--lean EXECUTABLE` is unisolated local diagnostics and can never produce verified production evidence. `--syntax-only` does not invoke Lean and makes no kernel or reuse claim. Both require dependency files when imports are declared. No previously submitted module is executed as a build script.

Trusted term inspection erases unused lets, beta-redex arguments and discarded constructor fields, follows owned definition aliases, and reports references to directly imported theorem constants that survive those implemented reductions. It does not perform general conditional/recursor reduction or prove that every dead branch has disappeared. Transitive imports are compiled but do not become extra direct-credit claims. Referencing definitions or types alone does not earn theorem reuse. A surviving reference is evidence of use, not proof of mathematical necessity or a guaranteed award; significance, artificial splitting and common-control limits remain separate adjudication concerns.
