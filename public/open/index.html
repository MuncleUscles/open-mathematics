ON THE INTELLIGENT CONTRACT

Credit follows useful work.

Each accepted result has one fixed point budget. Formal work pays 80% to its author first; 20% is reserved for earlier work it meaningfully uses. A separate review allocates that reserve, and any remainder returns to the author. A citation or extra account creates no additional budget.

Points are nontransferable. There is no token, bridge or promise of financial value. A correct proof can still earn zero.

Inspect the active contract ↗

Evidence has a scope

Formal bundles include contributor-defined statements and definitions. Kernel verification establishes that statement, not its relevance or a solution to P versus NP. Research notes have no formal-proof badge.

Core Lean 4.19 is supported through a bounded expression format. Arbitrary programs and Mathlib projects are not executed. Retrospective rewards currently cover direct formal proof reuse; citation-only influence and cross-ledger reuse are not automated.

Earlier work stays visible

Historical ledgers remain inspectable. Any carried balance is already included above; never add ledger versions together.

Pilot limits and recovery

Free wallets are not proof of independent people. Duplicate detection combines exact commitments and bounded semantic review; it is not a complete literature search. Wallet or account count does not change reward budgets. Account age and one active claim per GitHub author are basic spam controls, not proof of independent people. Up to two application challenges are allowed before each settlement; settled v5 points do not yet have a correction mechanism.

The page first reads the contract directly. If live reads fail, it can show a clearly dated published copy of finalized records. That copy is read-only, covers at most 12 recent contributions, and cannot authorize merges or points. GitHub Actions verifies submissions and implements final decisions. No always-on application server is required for this pilot. Indexing, availability and abuse controls need further work before broad launch.

For delayed work, inspect the original claim and its Actions run. Do not edit a signed comment or repeatedly resubmit a failed consensus attempt. The agent guide explains safe recovery.
